# AVA — find defects without a dataset

AVA spots visual defects on parts — scratches, chips, stains, stickers, missing features — from ordinary photos.
**No neural network. No training data. No GPU.** Every decision can be explained.

### ▶ Try it: **https://therizaev-ava-check.hf.space**
Works on a phone. Built-in examples (a scratched leather seat, a cracked brake disc) let you test it in one tap.

---

## Two modes

| Mode | Use it for | You need |
|---|---|---|
| **Surface check** | uniform surfaces — paint, plastic, metal, glass | **1 photo** |
| **Compare with reference** | complex parts — holes, ribs, logos | **1 reference photo + 1 photo** |

The answer is always one of three: **PASS** · **FAIL** (defect zones highlighted) · **RETAKE** (glare, blur, wrong angle).

## How it works

1. The photo is cut into small 8×8-pixel patches.
2. Each patch becomes a **pseudo-Boolean polynomial** — a method by Chikake & Goldengorin.
3. Making the light brighter or darker does **not** change which monomials the polynomial has. A real defect does.
4. AVA compares the patches — with the rest of the same surface (mode 1) or with the reference photo (mode 2) — and marks what is different.

Example from the paper: a patch gives `11 + 11y3 + 3y4 + 2y1y3 + 4y2y3 + 4y1y4 + 12y1y2y3 + 6y1y2y4`.
The same patch twice as bright (`2·A + 5`) gives `37 + 22y3 + 6y4 + 4y1y3 + 8y2y3 + 8y1y4 + 24y1y2y3 + 12y1y2y4` — **same monomials**, only the numbers change.

## Results

Synthetic test set (procedurally generated parts — not real photos yet), normal and changing light, thresholds set so that about 1 in 100 good parts is rejected:

| Method (compare with reference) | Defects found | Good parts rejected |
|---|---|---|
| **AVA** | **67.8 %** | **1.0 %** |
| SSIM | 67.3 % | 1.0 % |
| Census | 26.5 % | 2.1 % |
| Plain subtraction | 16.1 % | 2.1 % |

AVA finds **4× more defects than plain subtraction** and is on par with SSIM. Speed on a laptop CPU (Intel i5-13450HX): about **0.45 s** per comparison and **0.3 s** per surface check.
Full tables, all conditions and known failures: [eval/RESULTS.md](eval/RESULTS.md) · [eval/RESULTS_SURFACE.md](eval/RESULTS_SURFACE.md).

## Where it runs and what it costs

- **Where:** on a CPU only — the demo runs on a Hugging Face Space (2 vCPU); in a factory it runs on a mini-PC next to the camera, so images can stay on-site.
- **Speed:** under a second per photo (measured on an Intel i5-13450HX laptop; see the results files).
- **Cost:** no licences, no dataset, no GPU. One station = camera + stand + mini-PC.
- **Light, night, rain, plates:** changing or dim light is part of our benchmark; glare and hard shadows are known failures. AVA is an indoor inspection station, so rain and licence plates do not apply, and it never processes people or plates.

More detail: [docs/DETAILS.md](docs/DETAILS.md) · [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

```bash
pip install -r requirements.txt

python -m pytest -q        # tests
```

## Limitations

- A moving glare spot or a hard hand shadow can look like a defect — shoot from another angle.
- Surface check needs the photo to show **only** the surface (part edges and logos count as "different").
- Compare mode needs roughly the same angle as the reference.
- Results so far are on synthetic data; real-photo testing is the next step.
